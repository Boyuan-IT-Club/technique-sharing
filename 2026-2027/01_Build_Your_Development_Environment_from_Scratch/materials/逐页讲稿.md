## 仓库页面上的四个按钮

## 许可证：三档就够用了

LICENSE 决定别人能拿这份代码做什么。课程仓库本身用的就是 MIT，现场点开根目录的 LICENSE，看版权行和最后一段「无担保」。宽松许可 MIT、Apache-2.0 允许使用、修改、商用，甚至闭源，条件是保留版权声明；传染许可 GPL、AGPL 要求改动后再分发时同样开源，AGPL 把通过网络提供服务也算作分发；没有 LICENSE 就是默认保留所有权利，公开可看不等于可以用。注意 GitHub 站内 Fork 是平台条款给的例外，不改变这一点。装进来的依赖也有许可证，`pip install` 和 `npm install` 拿到的都是别人的代码。

## 包管理器是什么

包管理器就是帮你下载、安装、升级、记录版本，并把依赖一起装好的工具。分两层：apt 和 winget 管整台机器上的软件，apt 是 Debian/Ubuntu 的，winget 是 Windows 的，装 git、装编辑器都走它们。pip 和 npm 管语言自己的包：pip 装 Python 库，npm 装 Node 库，通常只装进当前项目。为什么需要包管理器：它记版本、自动带上依赖、换台机器一条命令重建；不集中管理，最后谁也不知道机器上装了什么。现场只演示 winget 查一个包：`winget search git`，真正的隔离靠后面的 .venv 和 node_modules。

## 写代码的工具 · 从编辑器到 IDE

先认四类。轻量编辑器加扩展：VS Code 和 Zed。Zed 用 Rust 写，打开大文件快，自带协作和 AI 面板，界面更简洁。重型 IDE：JetBrains 全家桶，IDEA 管 Java 和 Kotlin，PyCharm 管 Python，WebStorm 管前端，把编译器、调试器、重构和数据库工具都配齐，代价是启动慢、占内存、部分功能要授权。AI 编辑器：Cursor 基于 VS Code 的分支，把补全和对话直接放进编辑器。同一段代码在四种工具里都能跑，区别在打开后你手上有什么。

今天用 VS Code 不是因为最强，而是免费、跨平台、能连远端、扩展按需装。IDE 和编辑器的差别也不在名字：VS Code 本身不带编译器，跳转和补全来自语言服务，也就是 LSP，所以后面装了 Python 和 Pylance 才按得动 F12。

## 另外三个编辑器长什么样

同一个文件在这三个窗口里都能打开。让学生先找共同点：左边项目树、中间代码、底部终端和状态栏，位置几乎一样，差别在配色、字号和功能入口。Zed 更轻、更简洁；IDEA 的项目树和工具窗口更多，重构和调试入口都在菜单里；Cursor 的右侧多一个对话面板，改动能直接应用。结论：界面不是知识，三个都能上手，用哪个取决于团队和项目。

## 再往前一步 · 终端 agent 与桌面 harness

形态还在变。终端 agent 直接在终端里读仓库、改文件、跑命令：Claude Code 用 `npm install -g @anthropic-ai/claude-code` 安装，OpenAI 的 Codex 有 CLI、IDE 插件和 `codex app` 桌面入口，pi 走极简路线，用扩展和 skill 自己拼。桌面 harness 把同样的能力装进图形界面：DeepSeek 的 DSH 用插件架构，`npx @deepseek-ai/dsh web` 起一个本地面板；智谱的 ZCode 同时提供桌面、浏览器和终端三端。它们都是把模型、工具调用、文件系统和权限组合起来，行业里统称 harness。

## 什么是 VS Code

在看界面之前先认产品。VS Code 是微软 2015 年发布、2016 年出 1.0 的编辑器，源码开源、MIT 许可。定位是轻量编辑器加扩展：调试、语言支持、远程开发都是扩展补上来的。界面用 Electron 和 TypeScript 写，启动快，但内存占用比原生编辑器高。扩展市场里按需安装，一个窗口里能编辑、开终端、连远程。一句话：它本身只是个壳，能力来自你启用的扩展——后面装了 Pylance 才按得动 F12，就是这个意思。

## 打开项目：文件夹和工作区

打开项目有两个入口，容易混。文件 → 打开文件夹，选一个目录，就是单根工作区，标题栏显示「无标题工作区」；文件 → 从文件打开工作区，选一个 .code-workspace，文件里记录多个根目录和共用设置。区别两条：根目录数量，以及设置跟着谁走——.vscode/settings.json 跟着项目目录走，.code-workspace 跟着那一组目录走。本课两种都用：先打开仓库根目录读 README，再从文件打开 games.code-workspace 看两个项目并排。关闭时「关闭文件夹」和「关闭工作区」也是两件不同的事。

## 真实项目怎么学：后端、前端、从零实现

后端从 mall 开始，Spring Boot 写的电商系统，模块齐、代码量大，适合看真实分层；看不懂就从 spring-petclinic 这个官方最小示例入手。前端用 realworld，同一套 API 有几十种框架实现，可以直接对比同一功能在不同框架里怎么写；想读框架自身就看 vuejs/core 的源码。从零实现走 build-your-own-x，把 Redis、Git、Docker 各写一遍，比看十篇文章都实在。系统设计的概念用 system-design-primer 补。挑项目先看规模，一万行的先读，别一上来啃百万行的。

参考资料
mall  https://github.com/macrozheng/mall
spring-petclinic  https://github.com/spring-projects/spring-petclinic
realworld  https://github.com/realworld-apps/realworld
vuejs core  https://github.com/vuejs/core
build-your-own-x  https://github.com/codecrafters-io/build-your-own-x
system-design-primer  https://github.com/donnemartin/system-design-primer

## 拿到仓库之后怎么读

先跑通：按 README 装依赖、跑示例，别急着改。读入口：从 main 和测试文件开始，用 F12 跟两三层就够。让 AI 找：想学什么就让 AI 推荐仓库，clone 下来跟着做；也可以让它带你从零写一个小项目。GitHub Trending 每周扫一眼，知道大家在做什么，但别用追热点代替基础。

参考资料
GitHub Trending  https://github.com/trending

## 书与资料：先读这几本

Clean Code 讲怎么写才容易被别人读懂；人月神话讲为什么加人不等于加速，是工程和协作的底层常识；程序员修炼之道给的是可执行的习惯；重构讲怎么在不改变行为的前提下改结构。官方文档和公开课优先：Anthropic Engineering、OpenAI Cookbook、MIT Missing Semester。先读官方和源码，再看二手总结。

人月神话  https://openlibrary.org/isbn/9780201835953
程序员修炼之道  https://openlibrary.org/isbn/9780135957059
重构  https://openlibrary.org/isbn/9780134757599
